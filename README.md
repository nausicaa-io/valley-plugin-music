# Music & Podcasts

Music library and player with workspace-aware browser, panel, and player views that never roll back live playlists, queues, or playback.

Version 3 targets Valley plugin API 5 and uses SDK 6, tools 5, and testkit 6. Existing library data requires no migration. Valley’s persistent media runtime streams local files and prepares the next queued track without reading or decoding the entire file. Music’s backend owns queue advancement, shuffle, repeat, and play history, so closing application windows leaves local playback running. Queue transitions follow confirmed end events and are not sample-accurate gapless transitions. Playlist and artist relationships load every page; writes remain atomic. Removing more relationships than the host's 1,000-operation transaction limit reports an error without partially saving them.

## Install

Copy this repository into `<realm>/.valley/plugins/packages/local/music` or install its GitHub repository in Valley's plugin settings. The compiled `runtime/index.js` is included; Valley does not install dependencies or compile plugins on load.

## Development

Use Node 24.19.0 and npm 11.17.0, and Rust from `rustup` (the toolchain pinned in `rust-toolchain.toml`) with binaryen's `wasm-opt` at the version plugin-tools names. Run `npm ci` and `npm run check` in this directory. The package owns its dependencies, tests, localization, and vendored SDK/tool/testkit archives; no Valley app checkout is required. `npm run check` validates imports, types, tests, builds the artist-credits kernel in `src/wasm/` twice (the bytes must match each other and the `sha256` declared under `runtime.wasm` in `config.json`) and builds `runtime/index.js` and `runtime/assets/credits.wasm`. After a kernel change, commit the digest the build reports. Commit rebuilt runtime files with source changes.

The kernel computes every track's split artist names in one call, matching `trackArtists` exactly (`tests/libraryParity.test.ts` compares both on edge cases and randomized libraries). Music computes them in TypeScript until the kernel loads, when it cannot load, and for input it cannot encode faithfully (control characters in names, unpaired surrogates, libraries above 12 MiB of credit text).

## Song editing and playback

Right-click a song and choose **Edit song** to change its title, artist, album, featured artists, songwriter, author, composer, genre, year, lyrics, or cover. Covers can come from realm images, the image chooser, or drag and drop. Metadata is saved in Music’s library, without rewriting media-file tags. Rescanning preserves these edits; a stale editor reports a conflict instead of overwriting newer metadata.

The backend command catalog exposes `library.list/rescan`, `track.read/update/delete`, `playlist.read/create/update/delete`, and `artist.read/update/rename/merge` without opening a Music view. Read before editing and pass the returned `revision` as `expectedRevision`; playlist changes also require `expectedMembersRevision` from `playlist.read`. Artist edits require `expectedAliasesRevision`; merges require both artists’ revisions as `expectedSourceRevision` and `expectedTargetRevision`. Rescans require the tracks collection revision from `library.list`. These commands share the UI’s library operations, read embedded media tags, and save related dataset changes atomically. Deleting a track preserves its media file. Renaming keeps the previous artist name as an alias, while merging preserves target metadata and fills missing artwork or biography from the source. The UI’s undo history remains attached to its view.

The main page has one 38px header row: centered playlist/song breadcrumbs (the leading `/` returns to Home) and a search button beside the page menu that opens search in place of the breadcrumb (also Cmd/Ctrl+F; Escape closes it). Right-click the breadcrumb to switch to the realm-relative Music file path; this preference is saved. Video tracks offer Song and Video modes in one segmented control in the right sidebar. The switch matches the standard input height inside a 38px row. Media begins 5px below it in a shared square, height-capped frame; changing modes keeps the title, artist, and controls stationary. Covers fill the frame and videos preserve their proportions without an added black background. The host MediaSurface presents the same media element used for audio, including when presentation moves to PiP or another window. Shared transport commands wait for the host; an unknown outcome is shown without retrying playback. Music’s Stop also clears the upcoming queue.

Enable **Music** in Footer Rail settings for a cover-and-title button that opens the right-sidebar player. Music’s Footer details picker offers song, playlist, artist, favourite, queue, and known-duration totals. Library lists skip playback-clock renders, search results are memoized, and rescans use indexed path membership.

Music’s details panel presents plain key/value rows, cover paths, total duration, and per-artist song counts and minutes. Collaborations count their full duration for each credited artist, with aliases deduplicated per song; unknown durations are listed separately. The leading `/` breadcrumb returns to Home.

The Music home has an Artists row of round artist pictures sorted by song count; the picture plays the artist, the rest opens the artist page. While something plays, the tab icon is the headphones icon animated; idle it is the plain headphones icon (podcast icon in podcast mode). The playing artist's picture shows a level-bar equalizer at the bottom, and covers and rows keep the three-bar wave. Home’s header includes the active song while playing or paused. Recently played cards keep their order for the session, refreshing on library refresh or plugin reload while play history continues updating.

## Podcasts

The podcast button in the left panel header switches the library between Music and Podcasts. Set **Podcast folder** in Settings → Podcasts to a realm-relative folder; each direct subfolder is a show and its audio or video files are episodes (files directly in the folder form one show named after it). Episodes share the tracks dataset, playback, queue and history with songs but stay out of the music views. A show takes its name from the album tag its episodes share, else from the humanized folder name, and its cover from an image in the show folder (`cover`, `folder`, `artwork` first) or the first episode's embedded art. Episodes resume where they were left. While an episode is loaded the right sidebar becomes a podcast player: Listen and Watch modes, playback speed (0.75× to 2×, applied to episodes only), 15-second back and 30-second forward, and a button that marks a key moment, with no queue, history, previous or next. Below it, Key moments (jump, rename in place, remove; also shown as dots on the progress bar), Show notes and More from the show. The shrink button beside the title switches music and podcast players to a compact layout: a small cover (only when there is artwork) with the title beside it and no artwork or Listen/Watch switch, leaving more room for the lists below; the choice is saved (`playerCompact`). Key-moment ticks on the progress bar snap the scrubber when it comes within 10 px. Right-click an episode and choose **Edit episode** for its title, show, host, season, episode number, published date, guests, description and key moments; the cover comes first and shows the artwork currently used. Listening positions, key moments and the speed are kept in the plugin settings (`podcastProgress`, at most 300 episodes; `podcastMoments`; `podcastRate`).

## Workflow integration

The backend explicitly registers its supported blocks through `registerWorkflowContribution`. Workflow calls the owning operations with their original authentication, cancellation, grants, revisions, and receipts. The catalogue publishes Draft-07 parameter and port contracts; credential administration and approval bypasses are excluded. Workflow availability is configured separately in Workflow → Plugins. Existing account, connection, and profile settings remain owned by this plugin.

Workflow output collections are explicit: `library.list` → `$.rows`. Selectors are relative to each execution item’s `json`. Library listing deliberately selects rows, preserving parallel row revisions and the collection revision as metadata. Playback snapshots, nullable playlists, song IDs, artist aliases and rescan findings have no collection selector.
